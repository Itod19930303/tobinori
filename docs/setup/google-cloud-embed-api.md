# Google Cloud 準備手順: Maps Embed API（アプリ内に経路を埋め込む検証用）

Routes API は日本国内の公共交通ルートを返さないため、F-02 の代替として
「アプリ内の WebView に Google マップの経路（公共交通モード）を埋め込む」方式を検証する。
その前提となる Google Cloud 側の準備手順をまとめる。

- 作業者: **ユーザー本人**（Google Cloud Console の操作は Claude からはできない）
- 所要時間の目安: 10 分
- 費用: Maps Embed API は**無料**（従量課金なし）。ただし、プロジェクトに課金アカウントが
  紐づいている必要がある（Routes API 用に設定済みであれば追加作業は不要）。

## 先に知っておくこと

- 今使っている API キー（Routes API 用）には「Android アプリ限定」の制限がかかっている。
  WebView 経由のリクエストにはアプリの署名情報が付かないため、**そのキーは埋め込みには使えない**。
  このため、**埋め込み専用のキーを別に作る**。
- 埋め込み用キーは、アプリ内に保持されるため、第三者に取り出される可能性がある。
  被害を最小限にするため、「API の制限」で **Maps Embed API のみ**に絞る。
- **APIキーの値は、チャット・Git・スクリーンショットに載せない**（`env.json` にだけ書く）。

## 手順

### 1. プロジェクトを選ぶ
1. <https://console.cloud.google.com/> を開く。
2. 画面上部のプロジェクト選択で、今の Routes API 用キーがあるプロジェクトを選ぶ。

### 2. Maps Embed API を有効にする
1. 左メニュー「API とサービス」→「ライブラリ」を開く。
2. 検索欄に `Maps Embed API` と入力し、表示された「Maps Embed API」を開く。
3. 「有効にする」を押す。（すでに「管理」と出ている場合は、有効化済み）

### 3. 埋め込み専用の API キーを作る
1. 左メニュー「API とサービス」→「認証情報」を開く。
2. 上部の「認証情報を作成」→「API キー」を選ぶ。
3. 作成直後のダイアログは、キーを控えずに「キーを制限」を選ぶ（または一覧からキー名をクリック）。
4. 次のように設定する。
   - **名前**: `tobinori-embed`（分かりやすい名前で可）
   - **アプリケーションの制限**: 「なし」
     - WebView からのリクエストには Android アプリの署名情報が付かないため、
       「Android アプリ」を選ぶと使えなくなる。
   - **API の制限**: 「キーを制限」→ **「Maps Embed API」だけ**にチェックを入れる。
5. 「保存」を押す。
   - 設定が反映されるまで、数分かかることがある。

### 4. 手元の `env.json` にキーを追加する
1. `D:\develop\tobinori\env.json` を開く。（Git の管理外。コミットされない）
2. 既存の `MAPS_API_KEY` の下に、次の行を足す。値は手順 3 で作ったキーに置き換える。

   ```json
   {
     "MAPS_API_KEY": "（既存のまま）",
     "MAPS_EMBED_API_KEY": "（手順3で作ったキー）"
   }
   ```
3. 保存する。

### 5. Claude に完了を伝える
- 「できました」とだけ伝える。**キーの値は貼らない。**
- Claude 側で、キーが有効かどうかの確認と、検証用ブランチでの WebView 表示の試作に進む。

## 確認したいこと（検証のゴール）

- 現在地 → 目的駅の**公共交通ルートが、日本国内でも表示される**こと。
- 所要時間・乗換・路線名が、どこまで読めるか。
- 表示までの速さと、操作のしやすさ。

表示されない場合は、「Google マップアプリを開いて経路を任せる」方式に切り替える。

## 関連
- 経路が返らない原因の調査結果: Routes API の `TRANSIT` が日本国内で経路 0 件を返す。
- 現在の API キー（Routes API 用）の制限は、このキーの設定では変更しない。
