# 要件定義書 - トビノリ

## 1. 概要
- **アプリ名**: トビノリ
- **目的・背景（解決したい課題）**: 現在地から目的の駅までの最短経路情報のみを最速で提供したい。既存の乗換案内アプリは広告や情報量が多く、確認までに時間がかかる。
- **提供価値（一言で）**: タイパ（タイムパフォーマンス）を追求し、「調べる→確認する」までを最速にする乗換アプリ。広告や余計な情報を削ぎ落とし、「現在地→目的の駅」を最速で調べられることに特化する。

## 2. ターゲットユーザー
- **想定ユーザー像（ペルソナ）**: 通勤・通学中の社会人／学生。
- **利用シーン**: 寝坊や急な呼び出しなど、イレギュラーな出来事で頭の整理が追いついていない時に、とにかく最短ルートだけパッと確認したい場面。

## 3. スコープ

### 3.1 MVP（初期リリース）に含む機能
1. 現在地取得
2. 目的駅の検索（最短ルート表示を含む）
3. 検索結果で出た最寄り駅までの経路案内
4. 検索履歴（駅名入力に加え、過去の目的地履歴からも検索可能）

上記4点のみをMVPスコープとする。認証機能（OAuthログイン）はMVPから除外することとした（理由: 検索履歴がクラウド同期不要のローカル保存のみであり、ユーザーごとの出し分けが発生する場面が現状ないこと、また「調べる→確認する」を最速にするコンセプト上、起動直後にログイン画面を挟むことが好ましくないため）。

### 3.2 将来的に検討する機能（対象外）
- 時刻表閲覧
- 複数ルート比較
- 遅延情報・リアルタイム運行状況
- ショートカット登録
- 終電最速検索／時間指定検索
- アラーム機能
- 共有・ブックマーク機能
- 設定画面
- OAuthログイン（Google/X/LINE/Facebook）: 複数端末間での履歴同期等のニーズが生じた場合に将来再検討

※これらはデザイン参考資料（モックアップ画像）に将来構想として描かれているが、今回のMVPには含めない。

## 4. 機能要件

- **F-01 現在地取得**
  - 何ができるか: アプリ起動時にGPSで現在地を自動取得する
  - 誰が使うか: 全ユーザー
  - 画面/操作フロー概要: アプリ起動 → 位置情報権限確認・取得 → 現在地情報を検索の起点として保持

- **F-02 目的駅検索・最短ルート表示**
  - 何ができるか: 目的駅名を入力して最短経路を検索・表示する
  - 誰が使うか: 全ユーザー
  - 画面/操作フロー概要: 駅名入力 → 外部乗換案内APIへ検索リクエスト → 最短ルート結果を表示

- **F-03 最寄り駅までの経路案内**
  - 何ができるか: 検索結果で示された最寄り駅までの経路（現在地からの道順）を案内する
  - 誰が使うか: 全ユーザー
  - 画面/操作フロー概要: 最短ルート結果表示 → 「経路案内」操作でGoogleマップアプリを起動（インテント連携）し、徒歩ナビゲーションはGoogleマップ側に委譲する。アプリ内に独自の地図・道順UIは作り込まない（MVP方針で確定）。

- **F-04 検索履歴**
  - 何ができるか: 駅名入力に加え、過去に検索した目的地履歴から選択して再検索できる
  - 誰が使うか: 全ユーザー
  - 画面/操作フロー概要: 検索画面に履歴一覧を表示 → タップで再検索、または新規に駅名を入力

## 5. 非機能要件
- **パフォーマンス**: 「調べる→確認する」までを最速にすることを最優先。UIはsingle-column/single-purposeレイアウトで無駄な操作・表示を排除。
- **セキュリティ・プライバシー**:
  - APIキー等の秘密情報はコードに直接埋め込まず、安全に管理する（実装時の留意点）。
  - 検索履歴は端末内（ローカル）にのみ保存し、クラウド同期は行わない。
- **可用性・オフライン対応**: 電波が悪くオフライン状態（または劣化状態）になった場合は、裏側で自動的に見た目を変えてフォールバックするのではなく、「オフライン中です」等の表示でユーザーに明示的に状態を伝える方針で確定。
- **対応OS/端末**: Flutter（Dart）によるクロスプラットフォーム開発とし、Android/iOS両対応を見据えた設計とする。動作確認は開発者所有のAndroid 15端末で行うが、minSdk（対応最低バージョン）はAndroid 15専用に絞らず、Flutterの標準的な対応水準（Android 7.0以降を目安）とし、幅広い端末で動く汎用的な作りにする。iOS対応は1年以内を目安に将来対応予定。
- **アクセシビリティ**: 特に要件なし（未確定・今後検討）。
- **多言語対応**: 特に要件なし（未確定・今後検討、日本語のみを想定）。
- **プライバシーポリシー**: MVPでは認証機能を持たないため、当面は不要と判断。将来OAuthログインを導入する場合に改めて用意する。

## 6. 外部連携
- **経路検索データ**: **Google Maps Platform（Routes API等）を採用することで確定**。構造化JSONデータを取得し、トビノリ独自のデザイン（デザインシステムのカードUI等）でアプリ内に表示する。利用にはGoogle Cloudでのクレジットカード登録が必要（ユーザーは同意済み、無料クレジット枠内での運用を想定）。
  - 比較検討した他候補は不採用: 駅すぱあとAPI（無料だが構造化データが取れず自由なUI表示が困難）、NAVITIME API（個人開発者向けの継続利用可能な無料プランが実質なく有償契約前提）、ジョルダン乗換案内オープンAPI（「オープンな公開用途限定」でクローズドな個人利用には規約上使えない可能性が高く、利用審査・結果へのリンク表示義務もありコンセプトと不整合）、Yahoo!路線情報API（路線情報専用の公式APIが現状提供されていない）。
  - **予算アラートしきい値**: Google Maps Platformの予算アラートは、利用額が$1に到達した時点で通知を受け取る設定とすることを確定。
- **位置情報**: 端末GPSの利用が必須。
- **最寄り駅までの経路案内**: アプリ内に独自の地図・道順UIを作り込まず、Googleマップアプリを開いて徒歩ナビゲーションを委譲する（インテント連携）方式で確定（MVPスコープ）。

## 7. 制約条件
- **予算・期限**: 明確な予算枠・リリース期限は指定なし。まずは個人利用ツールとして無料の範囲で作る想定。
- **開発体制・スキルセット**: 個人開発。得意な言語・フレームワークは特になし。実装はClaude Codeを活用する。実装技術はFlutter（Dart）を採用（Android/iOS両対応を見据えたクロスプラットフォーム開発）。
- **既存システムとの整合性**: 特になし（新規個人開発プロジェクト）。
- **Apple Developer Program登録費用（iOS対応時）**: iOS対応（1年以内目安）に着手する段階で、年間$99のApple Developer Program登録が事実上必須となる。この費用負担への同意可否は現時点では保留とし、iOS対応着手時までに判断する（未確定事項として「10. 未確定事項・要確認リスト」にも記載）。
